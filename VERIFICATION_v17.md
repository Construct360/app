# v17 verification

Verified locally with isolated PostgreSQL (PGlite) and dummy browser accounts. No live project, real accounts, email service, GitHub upload or Vercel deployment was modified.

## Checks passed

- 85 timesheet database assertions: owner/company isolation, office access, private pay, server validation, save versus submit, stale versions, idempotent retries, return/approval, captured rates, account deletion retention, RLS, grants and restricted search paths.
- 10 upgrade assertions: a v16 quarter-hour draft and approved record survive v17 unchanged; migration rerun is safe; new quarter-hour saves are rejected; 0, 0.5, 8, 8.5, 23.5 and 24 are accepted; historical entries remain after correction.
- Full regression suite for auth/platform, clients/jobs, operations/planner, staff/storage, weather, vehicles and timesheets. Storage/Edge transports are emulated; this is not a live SMTP or hosted Storage test.
- Local browser → real SQL → UI: daily saves, reload persistence, a simulated lost save response and unchanged retry, explicit submission, office return/approval, own-only field roles and company isolation.
- Browser input checks reject 7.25, 8.1, 100, 24.5, -1 and exponent notation. Seven daily hours inputs render; no Job selector or add/remove-entry controls remain.
- Mobile dialog has no horizontal overflow. Desktop and mobile forms were visually reviewed; no browser page errors were observed.
- Branded owner and office PDFs were generated by the actual application builder. All rendered pages, including a long-name/long-notes multipage stress report, were reviewed. Office PDFs show daily rates/pay; owner PDFs remain hours-only.

## Security and compatibility

The v17 migration changes only the existing checked save RPC and its explicit permissions. Active membership, server-derived ownership, role checks, tenant locks, optimistic versions and audit writes remain. No new tables, grants to anonymous clients or client-side secrets are introduced. Existing jobs and historical timesheet allocations are not deleted.

The implementation follows Supabase's documented function search-path and privilege guidance: https://supabase.com/docs/guides/database/functions

Local fixture flag C360_TEST_V16 now installs v16 followed by v17, so the complete modern regression suite exercises the new save validation. The dedicated v17 upgrade test temporarily restores the old v16 RPC only inside its isolated database to test a realistic upgrade.
